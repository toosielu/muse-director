# Muse 实测风险与处理

## 来源与适用边界

来源是用户提供的“Meta Muse 实测100+条视频体感”八点摘要。原作者、测试日期、底层模型、账号配置与逐条原始产物未提供；本助手没有完成该100+条实测。下文将经验转成制作默认与针对性处理，不能据此量化失败率、保证提示词能消除缺陷，或当作官方永久规格。采用本轮实际界面、回传与用户决定修订能力记录。

## 1. 将 Muse 当作制作 agent 使用

交接包括本镜目标、参考绑定、声音路线和自检要求。按 [Muse能力配置](muse-capabilities.md) 要求抽帧、接触表、可用配乐/声音后期与技术检查，并回传证据。

抽帧优先覆盖首末状态、接触/交接、动作转折和剪切附近。当前指南自述Muse不能连续看听，不能要求它完成或声称完成试听及完整动态审片；这些交给具有实际能力的助手/用户。其抽帧、技术检查与后期处理分项回传。证据范围与通过判定见 [审查覆盖](workflow.md#审查覆盖)。

## 2. 底噪与未要求的人声、喘息声

新片明确只允许采用的对白、动作声、环境声与音乐；未经实际试听的生成音轨不宣称合格。安静镜头写明可闻来源；沿用已采用声音路线和声线，不无条件剥离合格原声。当前生成器自述不能接收音频参考、保证克隆或精确对嘴；指定干声用于可用后期，不误作模型声音输入。Muse负责可用处理，试听由有实际听音能力的一方完成。

- **声音路线未定**：按镜头需求选择原生同步或去掉原声的画面加独立混音。当前不假定Muse有静音生成参数；无声母版可通过后期剥离生成音轨取得。对声音要求高且无需原生对嘴的镜头，优先准备已确认干声与可控音效/音乐，再由 Muse 按实际能力整合；增加外部服务仍服从用户选择。
- **需要原生同步**：先验证代表对白和口型，试听没有对白的空隙与片头片尾；保留合格原声，定位不合格区间。
- **平稳底噪**：要求 Muse 在实际能力范围内处理，再试听对白自然度、尾音与静音段，避免降噪导致金属音或吞字。
- **未要求的女性喘息或其他人声**：标注出现区间。非平稳人声不能仅按底噪处理，也不能保证普通降噪能够去除。可取得分轨时处理污染轨；只有混合音轨且与台词重叠时，优先以采用干声重建声音或返修音频，并重新核对同步。静音不得删掉必要台词或事件声音。

请求干净画面母版、对白、音效/环境、音乐分轨与混音候选，仅在实际可取得时交付。没有分轨不要伪造。无实际听音能力时保留声音未核验；不靠Muse文本声明关闭杂音问题。未要求的人声与明显噪声属于待修缺陷，所述“女性”不是拒绝或替换已采用女声的理由。

## 3. 单次10秒与跨镜身份漂移

体感称单条最长10秒；用户随后提供的Muse指南自述为“约10秒、时长不可控”。当前按约10秒生成容量拆镜，8秒或更短是后期取用目标，不伪造duration参数或要求直接生成精确2秒。实测回传后记录生成时长与取用区间。其他能力变化更新项目记录，不将研究资料中其他模型的上限套到Muse。

长片按剧情事件、实测台词和动作窗口拆镜，不机械将每段填满10秒。跨镜使用同一采用参考与角色状态，复用可辨识的脸、发型、服装、比例、关键道具及画风；实际交接素材，不能仅在文字里声明“同一个人”。可用时利用通过的终帧/关键帧承接，但须核实入口，不承诺上一镜末帧必定可作为下一镜输入。

每镜回传检查身份，粗剪比较相邻镜头与统一角色参考。身份漂移先修参考、状态和机位，不把有缺陷的脸当成后续锚点继续扩散。保留合格镜头，返修失败镜头；仅一致的文字或参考不保证长片一致性。

## 4. 多人一致性与同时运动

默认避开多人同镜复杂运动，不投入连续尝试证明其可行。剧情需要多人时，优先用单人镜头、正反打、视线和空间承接表达互动；必要同框降低动作复杂度、错开动作时序，每段突出一个主要动作主体。人物分别绑定参考与位置，检查是否串脸、换装、交换肢体或混淆台词归属。

动作拆分仍须保留剧情必要的接触、交接与因果证据，不以孤立反应镜头掩盖未发生的关键动作。用户明确要求挑战复杂同框时才安排有范围的代表样片，说明未验证风险；失败后提出调度取舍，不自动追加预算或更换生成工具。

## 5. 内容拒绝与题材处理

用户报告枪支、校园、抽烟和性暗示题材容易被拒绝；这只是拒绝风险信号，不能写成所有相关词一律禁止，也不能推断 Muse 官方审核规则。先查看实际剧情与拒绝反馈，区分被拒内容、其他输入错误和未知原因。

出现拒绝时记录原任务、反馈与受影响镜头，不反复原样提交。提出符合平台规则的真实改编，例如按项目需要改为非武器冲突、移除吸烟动作或采用明确非性化的表达；会改变采用剧情、场景或人物时保留为待用户选择的方案。普通校园剧情不因标签自动改成另一故事。不要使用编码、谐音或隐蔽措辞伪装同一被拒内容以绕过审核，不声称任何替换词必然获批。

## 6. 写实皮肤变脏与年龄漂移

对用户报告的东亚女性写实呈现问题，以采用角色图、年龄、肤色和画风为依据检查；不要推断所有东亚女性必然产生这一缺陷。身份参考和美术目标需写清自然纹理、采用年龄与合适照明，避免无必要强化毛孔、污渍、粗糙或风化效果。

可按角色卡表达：“保持参考图的年龄与肤色，皮肤纹理自然，面部照明柔和均匀；不额外添加设定外污渍或加重年龄特征。”保留采用的皱纹、雀斑、疤痕等辨识特征，不自动美白、磨成塑料皮肤、年轻化或改变身份。卡通项目沿用卡通表现，不导入写实皮肤要求。回传与统一角色参考比较年龄、肤色和面部纹理漂移。

## 7. 幻肢与手臂动作

使用正向、可观察动作，写清采用肢体形态、谁的哪只手、接触对象、支撑位置、移动方向和终点；运动指令与实际参考、镜头裁切保持一致。不要堆叠手势、同时握持多个对象或让手臂交叉穿过身体。

例如：“角色右手握住杯柄，左手自然停在腿侧；右臂沿单一轨迹将杯子送到桌面，手腕与前臂连接连续，杯底接触桌面后松手。”按镜头需要保留肩肘腕链条的可读性，不要求画面外肢体全部出镜。复杂接触可调整机位、简化或拆分动作，但不删掉必要剧情事件。

连续检查准备、接触、移动、释放的区间，特别关注手臂数量、连接、手指/道具融合与瞬时增生。抽帧用于定位，连续播放用于判定；写得清楚能降低输入歧义，不能承诺完全规避幻肢。合格动作保留，不合格区间针对性返修。

## 8. 一个 Muse 旁聊对应一个生成任务

默认为每个独立生成任务使用干净的 Muse session/旁聊：本镜的一次候选生成及其自检围绕同一任务；换镜头、换目标或重生成新候选时使用新的旁聊，并记录与原镜头/版本的关系。这个规则指 Muse 旁聊，不要求新建 Codex 或其他助手的聊天。

项目总线程/本地工作单保留采用资产、总体分镜、声音决定和任务结果。生成旁聊只携带必要采用事实、参考、动作、声音与验收要求；不复制失败提示词全集和互斥方案。不假定新旁聊继承附件；重新挂载或实际确认干净的snapshot_id/media_handle可用，细则见能力配置。

“小批制作”指助手组织多个独立任务，不指把多个生成目标塞入同一个 Muse 旁聊。整片剪辑/混音是单独的整合任务，只接收采用素材及时间线。上下文污染是待验证假设，不能作为所有失败的自动归因；已有混杂会话出现串角色、旧台词或旧要求时，优先以干净任务包重建执行上下文并比较。

实际创建旁聊与投递使用已有授权和可用工具，不新增逐镜审批。若环境无法创建旁聊，准备任务包并说明待在新的Muse旁聊交接，不把“已准备”写成“已隔离/已发送”。

## 交给 Muse 的自检要求

根据本镜实际需求选取，不整段机械附加所有风险：

> 请按本镜目标做实际可用的抽帧和技术检查，重点覆盖关键动作前后、接触/交接、身份、肢体、必要皮肤年龄与接缝。能用图像或后期处理的问题先处理并说明方法，保留通过部分。返回真实视频、对应证据、处理说明和未完成项。不能连续看听的项目明确留未核验，不称抽帧为完整动态通过；试听及口型复核由助手/用户后续完成。

使用 [单镜交接模板](../assets/shot-handoff-template.md) 记录本轮用到的时长/会话、复杂度、声音与自检措施，后续按 [制作与验收流程](workflow.md) 复核。
