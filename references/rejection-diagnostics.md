# 拒收诊断与有限恢复

适用于生成未返回视频、输入被拒或工具报错。完整制作中由主控处理并继续整合，不把诊断菜单交给用户逐项选择。与 [自主成片](autonomous-delivery.md) 共用原镜头及项目额度；仅准备方案时不实际投产。

## 先保存事实，再判断下一步

保存实际错误原文、提交时间、输入及参考版本、附件可访问状态、平台可见任务状态和账单信息。报错码如 `integrity_check_failed` 本身不足以证明触发内容审核、某个词违规或图文过长；原因未知时明确写未知。不要把历史案例的成功组合当成本次必过规则。

先做不新增生成调用的检查：文件格式/损坏、附件实际绑定与访问、图文冲突、服务状态、提交是否已接受但还在处理。结果不明时先查询既有任务，避免重复付费提交。能修正的输入错误由主控修正；真实内容拒绝按平台规则作实质合法调整，不用编码、谐音、删除标签但保留同一内容的方式绕过审核。

## 原额度内选一个诊断变量

仍有额度且需要重试时，选能区分当前假设的一项变化，例如修复附件绑定，或精简与参考图重复的外观描述。保留必要身份、服装、眼镜等辨识点、必需动作及用户限制。冻结文案确需精简时升角色卡版本并重新编译受影响的待投产任务，保留旧提交；精简文字不授权改变人物身份。

用户明确要求原词对照时保留原文，精简方案另列为诊断版本，不称同文对照；实际执行采用稿仍遵循原样转交要求。

纯文本、参考图加短句、参考图加适中动作文本，是可选诊断设计，不是每次必须执行的三轮套餐。每次只改一个主变量；如果多项同时变化，记录混杂因素，不能据此锁定原因。原额度只剩一次就最多选择一次，耗尽后处理现有素材或明确受阻；换任务名、机位、拆镜和“探针”标签均不重置额度。

| 每次实际提交都登记 | 内容 |
|---|---|
| 归属与类型 | 原镜号、候选/诊断、实际任务引用；无平台ID时用本地主控标签 |
| 输入 | 角色卡/参考/提示词版本、唯一主变量、仍保留的必要要求 |
| 结果 | 实际接受/拒绝/等待/未知、错误原文、真实输出或未返回 |
| 资源 | 累计提交数、实际平台扣费或未知、镜头及项目剩余额度 |
| 判定 | 已证实事实、原因假设、下一步或停止原因 |

拒收、报错且无文件、诊断提交也计入实际提交数和本技能的保守尝试上限；没有账单证据时扣费写未知，不能称免费或返还额度。只有平台明确证明未发生生成且原资源规则允许恢复时才修订资源记录，保留证据与历史。

## 诊断输出何时可以复用

有视频仅证明该次调用得到输出。只有同样覆盖采用身份、画风、必要动作和参考绑定，且完成相应可做检查的诊断候选，才能作为代表样片或正式素材复用。纯文字探针不能证明参考图链路可用，静态人物成功不能证明复杂动作或长片身份稳定。可复用时无需再花一次额度重拍同样样片；未覆盖项目要求就不用于放行依赖镜头。

**示例**：S01 首次报未知完整性错误；每镜上限2次、项目余量1次。先查附件与实际任务状态；必要时用同一母版和升级后的精简身份卡做一次恢复，保留眼镜与开罐动作。无返回则停止新增调用，记录S01受阻；不能额外安排三种探针或用无动作人像替代开罐镜。

## 来源边界

用户在2026-10-03提供的一次Muse制作反馈（读取修订8）报告过拒收、诊断后成功、画内摄影设备及品牌文字等现象。未独立取得该项目原始工具日志或观看/试听媒体；图文密度触发拒收是该记录的解释，未建立单变量因果证据。本文件采用其恢复思路，不采纳后台架构、固定失败词或特定裁切像素作为通用结论。
