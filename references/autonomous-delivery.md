# 自主成片与主控职责

适用于用户把主题、简介、大纲或剧本交来，要求直接得到完整动画。仅要求写剧本、展示方案或试拍一镜时仍按该范围交付，不自动花费生成资源。用户指定协作审批时遵循其要求；自主成片是完整制作请求的默认方式。

## 决策由谁负责

一次原文实测、单镜候选与准备请求按 [执行范围](execution-modes.md) 收尾；自主成片不覆盖这些明确限制。普通必要事件返修在授权与剩余额度内由主控决定，不再等用户“拍板”。

| 事项 | 自主成片的处理 |
|---|---|
| 未指定画幅、画风、配角造型、转场、镜头数量 | 根据作品用途与已有约束自行选定，简短说明后继续；不列成待用户定夺 |
| 只有主题，需要自己写剧本 | 自行发展并选用适合制作的故事，保留用户指定的核心意图 |
| 已有剧本或角色母版 | 保留必要事件、台词、身份和结局；自主调整机位、拆镜、取用窗口与转场 |
| 样片、镜头候选与普通返修 | 主控按剧情职责、身份、动作证据和接缝选择，不能只因用户尚未看片而停住 |
| 听音或连续动态无法检查 | 保留未核验，完成可做检查与后期后交整片；不得要求用户逐镜看完才能继续 |
| 确实必须改变用户指定的核心情节、结局、人物或明确固定声线 | 先尝试保持核心的合法可执行方案；仍不能成立时集中提出一个关键问题及推荐方案 |
| 新服务连接、额外购买或超出明确资源限制 | 遵循实际权限与平台规则，汇总缺项；自主创作不代替这些权限 |

“主控选用”与“用户认可”分开。自主选用记录真实依据为用户的全片委托加主控选择，不能虚写“用户逐项批准”。工具字段 `baseline.approval_evidence` 可记录这段真实授权与选用依据；字段存在不意味着必须新增人工审批。没有实际授权时仍保留缺项。

## 从输入持续推进到全片

简短告知将制作什么，继而内部完成剧本、角色/场景母版、分镜与声音方案。未给时长时选能承载故事的有限范围，不把完整剧本任意缩成短样；超出当前资源时说明具体差额。不是每个项目都先把完整分镜表摆给用户审核。

投产前确定镜头清单、首次生成与必要参考的计划，以及有限返修额度。沿用用户预算与工具实际额度；无更具体重试要求时，每镜先一版，发现明确影响全片的问题才追加一次针对性生成，第二次仍失败则停止新增生成，用现有可用段整合或记录受阻；可准备改机位方案，实际重拍仍受原额度限制。不为轻微风格偏好生成大量候选，不把该额度宣称为用户设置。

身份母版与关键状态先稳定，再派发依赖它的镜头。确有风险的代表样片由主控检查和选用，是内部质量节点；其他无依赖任务可并行。用户要求全部完成不等于把尚未稳定的依赖镜头全部盲目并发。

一次追加可选择修正输入或在条件可比时同输入复跑，不能两者各加一次。用户配置不同次数时用执行范围的分项与总额度记录，参考/诊断/拒收等消耗不因换名重置。

## 独立任务负责制作，主控负责交片

主控保留轻量镜头记录：镜号、执行方式（可见旁聊或内部子任务/后台线程）、真实任务引用或本地主控标签、输入/参考版本、依赖、状态、文件、取用窗口和缺陷。内部任务不要求生成用户可见的旁聊链接；本地标签不冒充平台ID。拒收、诊断和候选提交共用原资源记录，见 [拒收诊断](rejection-diagnostics.md)。

每个独立生成任务使用实际可用的干净上下文，可由Muse旁聊或内部独立任务承载；仅改任务名不证明隔离。交接明确：执行任务只负责该镜与事实自检，向主控回传真实文件、实测信息与缺陷；不要求用户进入旁聊审批、不独自改变全片目标。回传“请主线程与用户定夺”时，主控自行承担镜头取舍，不自动转成用户任务。

主控须主动收齐结果、处理失败、选择可用段，更新实际时间线并剪辑混音。允许剪掉不必要的起始换景、把复杂动作拆镜或调整节奏，仍须保留剧情必需事件与已指定内容。检查取用后的区间与相邻接缝，不把整段原始素材的缺陷一律带入成片。

有实际任务等待/回调能力就使用，确认所有镜头进入已选用或明确受阻状态后继续整合，不能停在“已派发，等回来再说”。若平台必须用新一轮消息才能恢复执行，保存进度并如实说明这一限制，提供一次续做入口；不能声称不存在的后台持续工作，也不能让用户挨个催旁聊。

## 有限质量检查与结束条件

持续动态、声音、口型仅在实际能力可检查时判断。抽帧、解码和时间线只证明各自覆盖；无法检查不等于通过，也不自动成为每镜都找用户验收的理由。无对白项目可使用独立音轨以降低原生杂声风险，有必要台词时不能借静音删掉台词。

正常交付满足：所有必要剧情已进入同一全片；没有明知的空白占位、漏镜或重复内容；已完成实际可用的剪辑、音轨、字幕等要求；给真实可播放和可下载文件，报告实测时长与明确缺项。不能用旁聊链接集合、单镜文件、制作方案或“已经安排”代替全片。

若有无法排除的阻断，交已整合的当前版本并说明缺失事件、原因、已尝试方法和一个推荐下一步；必要剧情缺失时明确为部分作品。完整候选已交但看听覆盖不足时说明未核验；不得宣称全部视听通过。用户最终认可发生在交付之后，用户无需成为流程中的逐镜审核员。
