# 从研究资料提炼的 Muse 制作设计方法

在发展分镜、组织参考或优化提示词时读取。本文件把研究中的制作启发转成助手设计Muse任务的规则，具体交接见 [单镜交接](shot-handoff.md)，执行限制见 [Muse能力配置](muse-capabilities.md)，诊断与验收见 [制作流程](workflow.md)。

## 研究来源与迁移原则

2026-10-03已阅读 [Seedance官方提示词指南](https://docs.volcengine.com/docs/ark/seedance-2-5-prompt-guide?lang=zh)、[Jarvis文章](https://x.com/jarvis11x/status/2104397648438476868)、[Hell Grind案例整理](https://seedance-prompts-nu.vercel.app/case/hell-grind)及 [制作方项目说明](https://higgsfield.ai/@higgsfield.studio/projects/hell-grind)。它们是方法研究来源，Muse仍是本技能的制作方。

可迁移的启发包括：参考用途明确、身份与场景常量稳定、动作和空间关系具体、先验证风险再铺开、逐镜诊断、保留版本。以下是结合Muse能力的设计建议，不能称为原文逐字规则或已证明有效的实验结论。

案例整理页覆盖一条完整镜头提示词及两份规则，不是已核验的全片逐镜提示词；原项目使用Seedance 2.0，不能与2.5文档混成同一制作记录。固定生成次数、镜长、英语要求、三视图禁令和配音偏好只属于来源项目做法，不作为Muse通用规则。

## 将方法变成可执行设计

| 提炼的设计原则 | 助手在Muse任务中怎样设计 | 对应的可观察目标 |
|---|---|---|
| 每镜承担清楚的职责 | 先写本镜推进哪个事件、观众必须看见什么；区分必要动作与润色表情 | 核心事件发生，因果与结局符合采用稿 |
| 固定常量，逐镜只写变化 | 沿用采用角色母版、服装、道具与画风；本镜补表情、姿态、视角和状态变化 | 同一身份稳定，批准的变体不会混用 |
| 参考按用途明确绑定 | 只交接必要图片，说明各图控制身份、构图或道具；真实引用与顺序匹配文字 | Muse实际收到正确参考，素材用途没有冲突 |
| 空间有锚点 | 先确定场景物理位置和摄影轴线，再按本镜机位换算屏幕左右、视线和运动方向 | 相邻镜头可衔接，人物和道具没有无因换位 |
| 动作描述可见变化 | 写谁的哪只手、接触对象、支撑关系、相对运动和终点；从合理接触态开始也要保留必要原因 | 接触→移动→停止/交接成立，运镜不冒充对象运动 |
| 必要关键帧先合格 | 已有合格图复用；手部、造型或空间已错时先修图，再生成视频 | 避免把静帧错误扩散到视频和后续镜头 |
| 风险先验证，稳定方案复用 | 选真实高风险镜头做代表候选，通过后组织多个独立Muse任务并及时粗剪 | 身份、动作、声线等风险尽早暴露，减少整片返工 |
| 返修有主目标与回退点 | 从实际失败定位一个主变量；相关图文同步改，其余采用内容保留，声音问题优先后期 | 改动是否改善目标可比较，合格部分没有回退 |

不把参考图数量多当成稳定，也不把复杂提示词当成高质量。对多人互动按Muse风险设计单人、正反打或错时动作；必须发生的接触与交接仍要可见。角色母版的实际绑定和复核按单镜交接执行。

## 分镜到提示词的设计顺序

1. **剧情事件**：从采用稿提取本镜必要行为和前后状态，不擅自把生成困难的行为改成另一结局。
2. **可实现调度**：确定主要动作主体、景别、机位、接触与终点；复杂动作拆成有因果和承接的镜头。
3. **必要参考**：绑定本镜采用身份、场景/道具与关键帧。Muse当前生成只接收图文，音视频另列为后期素材。
4. **模型输入**：按需要写主体、场景、动作、镜头、风格和声音氛围。精简、互不矛盾；台词原文只写一次，管理字段放在制作任务层。
5. **检查目标**：列出必须看到、听到的结果与相邻承接，交给实际有能力的一方验证，不把抽帧或制作方声明当全片通过。

这些是设计检查点，不要求用户逐项填表或逐镜重新批准。已有采用稿和稳定资产从当前阶段继续；每轮只补本镜需要的设计。

Muse当前自述约10秒且时长不可控，分镜的短时长是回传后取用目标。事件节拍用于表达先后和动作，不冒充精确生成参数。指定声音用于实际可用后期；需要原生台词/口型时先验证代表候选，不保证图文能锁定声线。

## 同一想法的设计示例

笼统目标：“角色把盒子推过去，镜头很电影感。”

适用于Muse的设计稿：“沿用本轮采用角色和柜台/纸盒参考。固定中景，柜台A位在画面左侧，B位在右侧。右手掌接触一个蓝色盒子后侧，沿柜台推至B；柜台稳定，盒子相对柜台真实移动。盒子停下后右手才松开，左手停在腿侧。结束时盒子留在B，供下一镜承接。画风沿用参考；只允许必要动作音。”

这个教学稿需绑定真实参考，不能直接当作已执行输入。改进在于身份、空间、接触、变化和终点可观察，不承诺提示词一定避免幻肢或漏动作。完整交接与返修演示见 [制作与返修示例](worked-example.md)。

## 外部模型的专用能力怎样处理

研究文档中的API字段、模型ID、原生样片升级、视频编辑/延长、声音参考以及时长范围用于理解来源的能力边界，不进入Muse请求或作为Muse能力承诺。动作预演、样片验证与局部返修作为制作思路保留，分别落实为Muse可用图像修复、约10秒候选、实测剪辑和声音后期。

每次借鉴新案例，都提炼“它解决什么制作问题、我们怎样在Muse中表达、用什么实际结果检验”。效果是否改善按真实样片记录；来源平台成功不等于Muse已复现。

## 总导演草稿的补充方法

用户于2026-10-03提供了Grok bot的总导演评审草稿v2，草稿自己标注默认值未在Muse实测。吸收为 [角色卡、提示词模板与前后检查](shot-design-checks.md)、[可选题材知识](genre-profiles.md)、可见提交文本比对、单次容量证据和单文件指南自动生成。草稿关于原版“没有模板”或“禁止重试”的评价不是能力证据；其3次再2次、固定秒段、触屏示例、逐张用户确认或失败后删关键镜等做法不直接移植。
