# 对照与改进实验

用于“同一提示词为何效果不同”“照着示例把 Muse 效果提升”以及围绕真实失败改进交接方法。沿用 [制作与验收流程](workflow.md) 的质量优先级、权限和审查覆盖；不另建一套评分体系。先比较已有候选，再决定下一轮最有价值的改动。

## 冻结实际证据

恢复**原始提交 → 失败/阻断 → 助手替代建议 → 用户批准稿 → 实际执行与产物**的变更链，分别保留以下证据，不能混写：

- **来源词**：公开页或原作者展示的文字，记录链接、读取时点、原文文件及摘要。来源页可以发生变化。
- **原始用户提交词**：用户最初实际发给 Muse 的内容及附件；用户称“相同”先作为声明，能取得原文时再核对。
- **助手提出稿与阻断**：导演改写或替代稿，区分未采用建议；记录出现失败的具体阶段、可见结果或制作方声明，不以最终片倒推失败发生在视频生成阶段。
- **用户批准稿**：明确采用的版本、范围与证据，结合最新用户要求确定验收基准；缺少采用证据写 unknown，不能把建议自动升级为批准稿。
- **可见有效执行输入**：实际可读取的导演改写、分镜、生成指令、参考绑定和设置；只能取得一部分时注明覆盖，后台未公开输入写 unknown。

声称逐字相同时说明核对范围及换行、Unicode 等规范化方式。将风格、身份、姿态、空间、动作终点和时长的冲突单列为输入问题；这仍不是已生成失误的原因证明。清理冲突沿用用户已选方案，未知取舍标为试配，不顺带新增剧情或替换结局。

分别记录媒体文件及 SHA-256、实际时长与画幅、声音路线和可见后期。模型名、参考资产、参数、尝试次数及执行过程区分“已核实 / 来源声明 / unknown”。平台名不能充当底层模型证据；播放封面不自动视为生成首帧，提示词里的分辨率用词不自动视为输出参数。

未知可以保留，不能为了凑齐记录猜造日志。现有 `snapshot` 可把本轮实验单、原文及审查报告纳入来源快照；参见 [本地工具](toolkit.md)，本流程不要求扩展脚本。

## 确定比较能回答什么

分开报告两个判断：**采用稿执行度**检查实际产物是否完成当前获批目标；**示例质量差距**说明构图、动作、节奏、表现等可见区别。已获批的剧情变化记录为创作取舍或上游阻断后的调整，不能列为当前稿漏拍、未经授权改稿或模型失败。

**示例质量比较**可以说明这两个候选哪些可见结果更好，并用示例帮助定义表现目标。长度、画幅、参考、生成过程或后期不一致或未知时，不能据此宣布某模型总体更强、平台上限更低，或输入文字已经实现受控复现。

**受控比较**需要冻结采用故事和已知执行条件，明确唯一主变量与剩余未知；涉及不同模型时还需核实实际模型和参数。不能控制的条件直接列出，结论限制在证据范围内。初始同文但后续采用稿不同，不能仍称同提示词模型对照。

## 先验收事件，再看精致度

从当前获批采用稿和最新用户要求提取必要的可见事件、顺序与结局。每个事件至少说清“谁对哪个对象做了什么，前后状态如何改变”。对接触或交接写出对象原位置/持有者、接触、移动及结束位置/持有者。角色身份、关键道具形态、数量、支撑物与空间关系随事件一起检查。

采用稿中的关键事件缺失、因果不成立或结局被执行偏离，不能以可爱表情、装饰特效或漂亮构图抵销。获批删改的原稿事件不再属于这一验收清单。表情或符号若已表达要求的反应可作为证据，但不能自动代替明确要求的接触、传递或进入动作。

按**事件窗口**对齐两个版本，分别记录各自入点、持续与终点，不强行比较相同绝对秒数；故事不同只映射共同事件或可比较的镜头职责，差异另列。保持原画幅、比例和正常播放速度；并排查看可留边，不拉伸或悄悄裁切来制造一致。时长不同的节奏评价说明可用窗口差异。

抽帧可支持对应时刻的构图、身份与状态；缺少某帧不能证明事件缺失。完整事件是否发生、运动是否连贯，需要查看相关连续区间。证据只覆盖抽样时刻时如实标注，无法访问新片或无法听音的项目保留未核。

## 分层归因

报告把**观察、假设和未知**分开。先用变更链区分上游失败、获批改稿与当前稿执行偏差，再在来源词冲突、助手编译/删改、Muse 调度与可见参数、生成表现、剪辑/声音整合中定位原因；只在执行记录或保持条件的复测支持时缩小归因。制作方报告的失败仍标明声明依据，最终剧情不同本身不证明生成器执行失败。

推镜、整体画面缩放或图层平移不能直接证明对象相对环境完成了要求动作；二维动画可以合格，关键是动作和状态链可读。某局部在抽样中近乎静态，只证明这些样本的可见变化有限，不能据此断言后台使用静图、具体模型或某种生成方法。

## 安排最小改进实验

- **T0 复用当前候选**：绑定输入和媒体证据，建立最主要失败与已通过部分，不为建立基线重新生成。
- **下一轮只选一个主变量**：说明假设、目标可见结果、保持的已知条件，以及为主变量成立而必要的关联改动。可先保留当前获批故事、时长和制作路线，规范其事件与连续性。清理一份不自洽的输入方案可以统一相关描述，但不能从其改善反推某个单词的独立效果；恢复已被替代的原故事属于另一创意方案，不能混入同条件返修。
- **条件改变分轮记录**：延长时长、锁定参考、拆段/重调度是不同实验；按当前主要失败择一。一次采用组合方案也可以推进项目，但应标为组合优化，不能声称隔离了各因素。

先解决语义、动作因果和连续性，再优化表现细节。沿用已明确授权与预算；其范围支持后续试验时继续推进。没有执行依据时，先完成可审阅的工作单、输入和验收目标，待实际执行决策时依现有权限规则处理，不因采用本流程新增逐轮确认。

使用 [轻量实验单](../assets/experiment-template.md) 或等价记录；助手填写，用户无需先填技术表。未知条件不称为已固定。每轮保存输入版本与摘要、候选及 SHA-256、实际改动和回退点，不覆盖 T0 或已通过版本。

## 回传、复核与采用

按问题窗口登记实际**重制 / 沿用 / 失败**，映射到回传媒体版本、SHA-256 与时间段，不以整片文件存在代替逐项结果。关键问题所在镜头原样沿用，该问题继续开放；制作方称旧段“已验收”不能继承通过状态，需核对该版本的真实审查证据及覆盖。

发送或生成状态与审查状态分别记录。Muse 的完成声明不是改善证据；尚未检查重制段时只记待审，不能声称改善。取得真实回传后按相同事件目标检查，并复核相邻承接、声音、画幅及已通过指标有无回退。只能审画面时保留声音未核，缺失文件时不能沿用旧版本的通过状态。

失败保留具体阶段、可见错误码和原文证据，并标注是执行日志、制作方声明还是其他来源。错误码不等于原因解释，未知原因不猜造；发生阻断或重复失败时进入输入、参考、调度与可用制作方法的诊断，不继续堆限制词或无限重试。沿用既有授权次数与范围，不能因局部失败自行追加生成。

记录“改善 / 未改善 / 回退 / 未核”及证据，再决定采用、继续或回退到保留版本。连续无改善进入现有工作流的诊断节点，调整假设或制作方法，不自动增加预算。主目标达成且无关键回归，或达到预算/能力边界时结束本轮，说明已达到的效果与剩余缺项；不声称找到理论最优。
