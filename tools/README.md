# 后台工具

用户只需把[主文件](../muse-idea-to-short.md)发给 Muse。本目录给维护者和助手用，不生成视频，也不调用 Muse。

## 量视频的画幅和时长

需要本机装有 FFmpeg（`ffprobe`）。下载 Muse 的成片后运行：

```sh
python tools/u0_check.py downloaded.mp4 --target-aspect 0.5625 --min-seconds 6 --max-seconds 10 --min-short-side 720
```

`0.5625` 是竖屏9:16（宽÷高），横屏16:9写 `1.7778`。输出 JSON：画幅或时长不对是 FAIL（返回码2）；短边偏小或疑似中间有硬切是 WARN（返回码0）；工具没跑成是 UNVERIFIED（返回码3）。疑似硬切也可能是闪光或场景变化，要自己看片确认。工具不会改动视频。

### 源素材与交付比例分开检查

`--aspect-tolerance` 默认仍是宽高比数值的绝对差 `0.01`，不是1%或“同为横屏就行”。不因本轮3:2输出而放宽：1152×768对16:9仍为FAIL。先报告偏差、核对真实入口，不反复生成。只有用户明确接受3:2时，才按 `--target-aspect 1.5`检查；保留原16:9未通过的记录。

用户若同意3:2源素材、最终裁成16:9，分别保存源文件与成片并作两次检查：源文件用已批准的制作比例1.5，成片仍用1.7778。工具只检查，不执行裁切或替用户授权。保持宽度时1152×768裁为1152×648，损失原高度15.625%，居中上下各60像素；1920×1280裁为1920×1080同理。先预览是否切掉人物、剑或其他关键物件，不裁首帧冒充原目标合格，不改显示比例或拉伸来造通过。

竖屏1152×2048为精确9:16；704×1248约0.5641，与0.5625的差约0.0016，在原容差内。704短边低于默认720时会另报WARN，这是尺寸提醒，不是画幅FAIL。裁后1152×648也可能因短边报WARN；项目短边要求单独约定，不能把画幅通过混为所有规格通过。

本轮案例与依据见[场景记录](../testing/scene-continuity-results-2026-10-05.md)。测试补测保留16:9文字、接受3:2实验素材的例外不适用于正式交付。

## 包检查

```sh
python -m unittest discover -s tools/tests -p "test_*.py"
python tools/check_package.py
```

`check_package.py` 检查必需文件、主文件的必备小节、本地链接和测试集是否齐全，并报告主文件长度，不设主文件字数上限。`drafts/` 只检查文件和链接，不把草稿当成制作规则。它只检查文字结构，不代表视频效果。
